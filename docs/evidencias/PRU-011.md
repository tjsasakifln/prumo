# PRU-011: evidências de navegação 2D/3D

**Registro inicial:** 19/11/2026. **Revisão local:** 20/11/2026. **Estado:** código implementado, testes locais e build WASM executados; a issue permanece aberta. A evidência de execução dos backends reais, a campanha humana de acessibilidade e a publicação da matriz ainda não estão completas.

## O que foi implementado

- Projeções ortográficas de planta XY, corte XZ e câmera 3D, simultâneas ou alternadas. Segmentos e contornos vêm das peças de domínio. Eixos e níveis aparecem como guias tracejadas com rótulos, sem ligação automática.
- Seleção por UUID compartilhada por vistas, árvore e propriedades. Lista inclui ocultos e outras cotas; cliques sucessivos alternam objetos sobrepostos. Ocultar e isolar conjuntos inclui componentes físicos.
- Recorte por intervalo X/Y/Z, enquadramento, câmera e deslocamento com entrada numérica e botões. Tab, Enter, setas, Home e ampliação/redução oferecem alternativa sem arraste.
- Foco visível, texto além de cores, escala de 100% a 200%, alto contraste e localização dos apontamentos geométricos da revisão consultada.
- Estado de vista separado da revisão técnica. UI e MCP usam `ViewCommand` e `ViewReport`; o relatório identifica projeto, revisão e SHA-256 canônico do modelo. Uma falha visual não apaga o projeto.
- Exportação nativa autorizada de uma cópia JSON completa e visualizador Rust/WASM de consulta. Importação conserva identidades, revisão e unidades e valida a representação JSON antes do projeto.

Não há cálculo, dimensionamento, renderização sólida, perspectiva ou persistência de autoria no navegador nesta entrega. O corte é uma vista XZ e um recorte espacial explícito; não se anuncia um sistema completo de planos de corte arbitrários.

## Evidência visual CPU

O exemplo `apps/prumo-desktop/examples/viewport_gallery.rs` gera o projeto pelo `Desktop` e seus comandos. Com `PRUMO_VIEW_MESH_EXPORT`, executa a UI egui real, exporta meshes, recortes, cores e o atlas de fontes. `scripts/render_egui_meshes.py` produz PNG por rasterização CPU aproximada desses dados. Essa evidência serve para inspecionar conteúdo, posicionamento e escala; não qualifica driver, composição de janela ou browser.

```bash
PRUMO_VIEW_MESH_EXPORT=artifacts/view-100 cargo run -p prumo-desktop --example viewport_gallery --locked -- artifacts/view-project.json
python scripts/render_egui_meshes.py artifacts/view-100 artifacts/view-100.png
PRUMO_VIEW_CONTRAST=1 PRUMO_VIEW_MESH_EXPORT=artifacts/view-150 cargo run -p prumo-desktop --example viewport_gallery --locked -- artifacts/view-project-150.json
python scripts/render_egui_meshes.py artifacts/view-150 artifacts/view-150.png
```

Os metadados de cada exportação registram `native_backend_executed: false` e `web_browser_executed: false`, SHA-256 dos meshes e da imagem e o snapshot do modelo. A imagem precisa ser aberta e inspecionada na rodada que a produzir; a existência do script não é uma inspeção.

Nesta rodada, foram abertos e inspecionados os PNGs de [100%](PRU-011-egui-cpu-100.png) e [150% com alto contraste](PRU-011-egui-cpu-150.png), com seus [metadados de 100%](PRU-011-egui-cpu-100.json) e [150%](PRU-011-egui-cpu-150.json). As três vistas mostram a viga superior selecionada também por texto; comandos, propriedades e rótulos em português aparecem sem recorte horizontal. Um erro inicial do exportador de ensaio, que confundia pixels e pontos lógicos em 150%, foi corrigido antes dessas imagens. Os arquivos finais registram a versão de Python, NumPy e Pillow e o hash do rasterizador. Cada execução cria uma fixture própria; a comparação nativo/web abaixo usa um único JSON e seu snapshot exato.

## Captura do backend nativo no CI

`PRUMO_VIEW_SCREENSHOT` ativa uma captura por `Context::request_screenshot` do egui 0.37.0. O exemplo espera pelo menos cinco quadros, recebe os pixels do backend glow, grava PNG e metadados e encerra a janela. Uma janela fechada sem callback, captura vazia ou timeout retorna erro. O código não trata meshes CPU como captura nativa. A gravação usa `image 0.25.10`, somente como dependência de desenvolvimento, com PNG e sem features padrão.

```bash
cargo build -p prumo-desktop --example viewport_gallery --locked
mkdir -p dist/native-evidence
xvfb-run -a -s "-screen 0 3200x3200x24" env LIBGL_ALWAYS_SOFTWARE=1 PRUMO_VIEW_SCREENSHOT=dist/native-evidence/native-100.png target/debug/examples/viewport_gallery dist/view-project.json
xvfb-run -a -s "-screen 0 3200x3200x24" env LIBGL_ALWAYS_SOFTWARE=1 PRUMO_VIEW_CONTRAST=1 PRUMO_VIEW_SCREENSHOT=dist/native-evidence/native-150.png target/debug/examples/viewport_gallery dist/view-project-150.json
```

O workflow Linux instala Xvfb/Mesa e executa as duas capturas no backend distribuído. Registra também `glxinfo -B`, hash do executável, da imagem e o relatório da vista. **A execução e inspeção dessas capturas reais permanecem pendentes nesta estação bloqueada.** Mesa em software no CI é um backend real de janela/renderização, sem representar uma campanha de placas gráficas ou um ensaio humano com leitor de tela. Perda real de contexto nativo continua pendente.

## Build e ensaio web reproduzíveis

```bash
cargo install wasm-bindgen-cli --version 0.2.130 --locked
python scripts/package_web.py
PRUMO_VIEW_EXPORT_ONLY=1 cargo run -p prumo-desktop --example viewport_gallery --locked -- dist/view-project.json
node scripts/verify_web.mjs dist/prumo-web dist/view-project.json dist/web-evidence
```

O empacotador exige a versão exata do binding, verifica a extração e todos os hashes e inclui avisos de terceiros, instruções e manifesto. A verificação no browser usa Chrome/Chromium e CDP para abrir o HTML distribuído, importar o projeto nativo, comparar o snapshot, operar controles por teclado, conferir árvore acessível e escala e injetar perda real do contexto WebGL. Capturas e relatório ficam separados do manifesto de build. O CI Linux executa esse roteiro sem dispensar os testes nem o upload nativos.

No CI, o JSON de `native-100` é aberto no browser, sem gerar outro projeto entre ambos. O quarto argumento opcional de `verify_web.mjs` recebe `dist/native-evidence/native-100.json`, confere UUID, revisão, snapshot e hash da captura antes da abertura web e vincula essa evidência ao relatório final.

**A execução local do roteiro de browser está pendente pelo bloqueio de sockets acima.** Resultado futuro do CI deve ser vinculado ao commit e inspecionado antes de marcar o critério como concluído. A compatibilidade humana com leitores de tela no Linux/Windows e em browsers continua um ensaio próprio, mesmo quando a árvore acessível automatizada passa.

## Pendências obrigatórias

- Concluir execução e inspeção da janela nativa com o backend distribuído, inclusive perda/recuperação real de contexto onde suportada.
- Concluir execução e inspeção do mesmo projeto no browser do CI e registrar browser, hash do WASM, snapshot, capturas e resultado.
- Exercitar as partes compatíveis com leitor de tela humano nos destinos declarados; registrar operações e limitações por plataforma.
- Publicar e verificar os artefatos da matriz Linux/Windows e do visualizador web. Respeitar a dependência e a ordem de integração; a implementação em branch isolada não conclui a issue anterior.
