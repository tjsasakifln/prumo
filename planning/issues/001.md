# PRU-001: Fundação executável com projeto BIM e MCP desde a origem

## Objetivo

Abrir o desenvolvimento com uma fatia real do produto, utilizável pela interface e por um cliente MCP.

## Ordem de implementação

**Etapa 1/250. Fase 01: Base BIM, MCP e verificação.**

Primeira issue da sequência. Consultar o planejamento e confirmar a base atual do repositório antes de iniciar.

Regras: [AGENTS.md](https://github.com/tjsasakifln/prumo/blob/main/AGENTS.md), [PRD](https://github.com/tjsasakifln/prumo/blob/main/PRD.md) e [critério de conclusão](https://github.com/tjsasakifln/prumo/blob/main/docs/CONCLUSAO-ISSUE.md).

## Escopo

- Workspace Cargo com aplicações e crates Rust por responsabilidade, comandos de desenvolvimento e CI em Windows e Linux
- ADR inicial de aplicação desktop com interface própria em Rust, reaproveitamento web/WASM, domínio isolado e processo de cálculo separado; comparar frameworks Rust sem reabrir a escolha da linguagem
- Criar, salvar e reabrir projeto mínimo com unidades, revisão, um objeto físico e sua identidade analítica
- Servidor MCP local funcional usando os mesmos comandos de criação e consulta da interface
- Contratos de domínio extensíveis para disciplinas, ambientes, redes e portas tipadas; ensaio de persistência e comando sem apresentar cálculos futuros como disponíveis
- Versionar Cargo.toml, Cargo.lock e rust-toolchain.toml com versão estável exata; declarar edition, rust-version, resolver, features, targets e dependências nativas do pacote

## Critérios de aceite

- [ ] Instalação limpa executa a interface e o servidor sem edição manual de arquivos de configuração
- [ ] Projeto criado pela interface é consultado e alterado pelo MCP, e o contrário, com identidade e revisão preservadas
- [ ] Nenhum cálculo simulado é apresentado como resultado estrutural e nenhum botão essencial é apenas decorativo
- [ ] Componentes usados nesta primeira etapa já passam por triagem de licença, versão e dependências; a issue 3 amplia a qualificação, sem autorizar uso prévio não examinado
- [ ] MCP inicial é stdio local, limitado ao projeto selecionado, sem shell, SQL ou caminhos livres; autorização básica existe desde a primeira operação
- [ ] Interface, modelo mínimo, comandos, persistência e servidor MCP são implementados em Rust e usam o mesmo domínio; não existe segundo núcleo de produto em TypeScript, Python ou C++
- [ ] ADR compara autoria Rust nativa e/ou Rust/WASM com o mesmo caso BIM, incluindo acessibilidade, navegação 2D/3D, operação local, impressão e empacotamento; recursos experimentais ficam identificados

## Verificação e evidências

- [ ] Teste de ponta a ponta UI > salvar > reiniciar > consultar por MCP
- [ ] Cliente MCP real negocia a revisão suportada e rejeita versão desconhecida
- [ ] CI executa cargo fmt --all -- --check, Clippy, testes e build com --locked para os targets/features distribuídos; registra o compilador efetivo e as dependências nativas
- [ ] Executar a operação BIM real por interface Rust e cliente MCP; confirmar equivalência após reabertura e erro de entrada, sem usar respostas fixas como implementação

- [ ] Conferir as obrigações dos arquivos e dependências efetivamente incorporados. Candidato listado não significa homologação; nomes sem ficha documental permanecem com pesquisa pendente.

## Contratos transversais

- [ ] REQ-15 e TEC-RUST-01: implementar em Rust todo código próprio do produto, incluindo interface, BIM, regras de engenharia, motores, CLI e MCP. Usar workspace Cargo e toolchain Rust fixada, conforme [RUST.md](https://github.com/tjsasakifln/prumo/blob/main/docs/RUST.md).
- [ ] Componentes externos em outras linguagens exigem integração e qualificação conforme [RUST.md](https://github.com/tjsasakifln/prumo/blob/main/docs/RUST.md) e a política de reuso. A integração não autoriza nova lógica própria de produto em outra linguagem. Ferramentas de manutenção do planejamento podem usar outras linguagens.
- [ ] Interface e MCP usam os mesmos comandos e validações; novas funções relevantes ampliam ambos, inclusive após a etapa 99.
- [ ] Unidades, identidades, autoria, revisão e estados de resultado permanecem rastreáveis. Mudança relevante invalida evidências dependentes.
- [ ] Código integrado, revisão independente e evidências reproduzíveis constam da entrega. Nenhuma pendência obrigatória é retirada para encerrar a issue.
